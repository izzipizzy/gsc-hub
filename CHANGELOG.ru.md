## [0.9.0] - 2026-10-06

### Как обновиться

```bash
git pull
docker compose up -d --build
```

Новые таблицы SQLite создаются автоматически при запуске; существующие данные
остаются в примонтированном томе. Перезагрузите открытые вкладки. Опциональный
прокси для проверки ссылок и ключ индексатора задаются в настройках.
Платные отправки на индексацию автоматически не запускаются.

### Добавлено
- **Фильтры URL домена.** Сохраняемые исключения страниц и поиск в Striking
  Distance по части URL, включая условия «содержит» и «не содержит».
- **Покупка на свой path.** Можно купить ссылки на страницу текущего домена
  со своим текстом через общий попап покупки; покупка отображается в событиях.
- **Проверка купленных ссылок.** Еженедельная и ручная проверки показывают
  наличие ссылки, изменения анкора и атрибуты rel. Пропажа подтверждается второй
  проверкой минимум через сутки. Поддерживается опциональный SOCKS4/5 с
  авторизацией; проверка использует User-Agent Googlebot и читает HTML без JS.
- **Пульс поставщиков.** Количество и проценты по поставщикам, история живых,
  пропавших ссылок и ссылок с неизвестным статусом.
- **Индексаторы и отправка из домена.** Настройка NeuralIndexer, отправка
  страниц или sitemap с дочерними картами, подсчёт URL, стоимости и баланса до
  отправки. История хранит принятые URL и списания; повторная отправка использует
  тот же идентификатор запроса. Приём сервисом не означает индексацию поисковиком.
- **Видеообзор.** 90 секунд на вымышленных данных с русской озвучкой и
  субтитрами; видео доступно из обоих README.

### Изменено
- Добавлена сортировка колонок Striking Distance. Страница сайта запоминает
  выбранное гео и диапазон дат.
- Статусы и размещения поставщиков кешируются, доступно ручное обновление.
  Прогресс опрашивается во время активной проверки ссылок.

### Исправлено
- Проверка не отмечает несовпадение анкора, если ожидаемый текст не задан в
  заказе. Предупреждения об атрибутах rel сохраняются независимо от анкора.
- Битый JSON при индексации возвращает ошибку клиента вместо ошибки сервера.
- Маски URL больше не используют регулярные выражения с экспоненциальным перебором.
- User-Agent запросов индексации и sitemap берёт версию из манифеста.

## [0.8.0] - 2026-09-29

Новый вид, графики, которые сами объясняют скачки, и вход для скриптов и
ИИ-агентов. Существующие экземпляры мигрируют при старте, настраивать ничего не
нужно.

### Как обновиться

```bash
git pull
docker compose up -d --build
```

Схема мигрирует вперёд при старте (новые таблицы `api_keys`, `site_events`,
`magiclinks_purchases`; ничего не удаляется). Данные переживут: SQLite лежит в
примонтированной `./data`. Откат - `git checkout v0.7.1 && docker compose up -d
--build`; лишние таблицы старая версия просто не замечает. Если во время
обновления была открыта вкладка, перезагрузите её один раз: вкладка со старой
сборкой может показать страницу ошибки на первом клике. Подробности, включая
последовательность для ИИ-агента: [Обновление](README.ru.md#обновление).

### Добавлено
- **Графики с контекстом.** На странице сайта полный график трафика с полосами
  апдейтов Google; страница Sites начинается с пульса портфеля на тех же
  полосах.
- **События сайтов.** Отмечайте склейки доменов, переезды и что угодно на
  таймлайне сайта; отметки видны на графиках и карточках дашборда, `/events`
  показывает все сразу.
- **Машинный API с ограниченными ключами.** Ключи создаются на `/api`,
  показываются один раз и хранятся как sha256. Ключ можно ограничить набором
  сайтов, остальное для него отвечает `404`. Ручки: сайты, запросы, главная
  посадочная страница по запросу, гео и события сайтов. Документация для
  агентов - `/api/v1/doc.md`.
- **MCP-сервер** на `/api/v1/mcp`: девять инструментов только на чтение и
  четыре скила для агентов, которые отдаются как промпты MCP и файлами. MCP
  ничего не пишет и не тратит деньги. Подключение:
  [docs/MCP-SETUP.md](docs/MCP-SETUP.md).
- **Интеграция с серпмонитором** (опционально): колонка реальной позиции и
  кнопка «проверить» на странице сайта (`SERP_MONITOR_URL`,
  `SERP_MONITOR_TOKEN`, `SERP_API_TOKEN`).
- **Покупка ссылок** (опционально): посты со ссылками на страницы в striking
  distance покупаются прямо из таблиц striking - через
  [FieldLink](https://seoboost-root.info/r/flt_czhTpL1GKPqQXI2h1c463ULMS2IEzV6fjJow2hiGlMg) (партнёрская ссылка)
  или 369Team (`magiclinks.online`, ключи - в Telegram
  [@links_369](https://t.me/links_369)). Окно по умолчанию берёт провайдера с
  большим балансом и перепроверяет цену прямо перед оплатой; на `/magiclinks` - заказы
  обоих с прогрессом и, у FieldLink, статусом индексации. Таблицы striking
  отмечают уже купленные пары «запрос + URL».
- **Дашборд:** карточки сайтов в стиле OpenGSC и отдельный блок **«Сегодня»**,
  который не сравнивается ни с чем, пока день ещё набирается.

### Изменено
- **Редизайн.** Плотный вид в стиле торгового терминала по всему приложению;
  Portfolio - в верхнем меню.
- **Ответы Search Console кешируются в памяти до 60 минут.** Переходы быстрее,
  квоты хватает дольше; **Refresh** сбрасывает кеш, рестарт начинает с нуля.
  Ответы Search Analytics на диск не пишутся.
- **`.env` для Docker Compose необязателен** (Compose 2.24+): свежий чекаут
  сразу стартует в setup-визард.

### Исправлено
- **`pnpm dev` на свежем клоне снова работает.** Без заданного `ORIGIN` охрана
  доступа считала dev-сервер доступным снаружи и отвечала `503` на всё, включая
  setup-визард. Теперь dev-сервер сам сообщает свой loopback-адрес, а текст `503`
  подсказывает, что задать.
- Период работает на вкладках страницы сайта, а поисковые операторы (`site:` и
  подобные) больше не попадают в списки ключей.
- Privacy Blur закрывает карточки сайтов и метрики на дашборде.
- MCP отвечает той версией протокола, которую просит клиент, и прячет мусорные
  запросы так же, как экраны хаба.

## [0.7.1] — 2026-08-26

Для запущенного экземпляра не меняется ничего. Изменилось то, как этот проект
выпускается: инструмент публикации теперь лежит в самом репозитории.

### Как обновиться

```bash
git pull
docker compose up -d --build
```

Обновляться незачем — приложение побайтово то же, что в v0.7.0. Обновляйтесь,
только если хотите иметь инструмент выпуска у себя в чекауте. Данные в любом
случае переживут: SQLite лежит в примонтированной `./data`, а не в образе.
Откат — `git checkout v0.7.0 && docker compose up -d --build`. Подробности,
включая последовательность для ИИ-агента: [Обновление](README.ru.md#обновление).

### Изменено
- **Релиз — одна команда.** `scripts/publish.sh` собирает публичное дерево,
  коммитит его потомком предыдущего релиза, тегает, пушит ветку и тег одной
  атомарной операцией и создаёт релиз на GitHub. Команда идемпотентна: повтор
  после обрыва связи доделывает релиз, а не начинает второй. Force не
  используется никогда, а если публичная ветка сдвинулась — публикация
  отказывается идти.
- **Что не уезжает наружу, теперь объявлено, а не держится в памяти.**
  `.publicignore` перечисляет это синтаксисом gitignore, а любой путь, который
  впервые станет публичным, печатается и требует подтверждения руками до того,
  как что-то будет запушено.
- Само приложение не тронуто — под `src/` изменений нет.

## [0.7.0] — 2026-08-24

### Как обновиться

```bash
git pull

```

Данные не теряются — SQLite лежит в примонтированной `./data`, а не в образе,

### Добавлено

  изменений. В контейнере это тег релиза; на dev-хосте рядом показан коммит
  рабочего дерева, потому что в образе нет ни git, ни `.git`.

## [0.6.8] — 2026-08-23

Международные домены и остаток работы над branded-разбивкой.

### Исправлено
- **Сайт, добавленный как `https://пример.рф/`, получает пригодный
  бренд-термин.** `new URL()` приводит международное имя хоста к ASCII-форме,
  поэтому такое свойство приходило как `xn--e1afmkfd.xn--p1ai` и давало термин,
  которого нет ни в одном русском запросе, — тогда как тот же сайт, добавленный
  как `sc-domain:пример.рф`, сохранял кириллицу. Один сайт, две разные разбивки,
  в зависимости от того, как его завели. Теперь имя хоста декодируется до вывода
  термина.
- **Термины и запросы сравниваются в одной форме нормализации Unicode.** Термин
  с `é`, записанным как `e` и комбинирующий акут, не совпадал с тем же словом,
  набранным преднаписанным символом, — и наоборот.
- Страница сайта теперь показывает, какие из введённых терминов достаточно
  коротки, чтобы матчиться только как отдельные слова. Правило действовало с
  0.6.6, но было невидимым: человек, вписавший `co`, никак не мог узнать, что
  оно работает иначе, чем `example`, и почему разбивка выглядит странно.

### Безопасность
- Декодер punycode ограничен по размеру, а его арифметика проверяется.
  Написанный без защит от переполнения, которых требует RFC 3492, он на метке из
  нескольких сотен continuation-цифр разгонял рабочий множитель до `Infinity`,
  после чего цикл подстройки bias делил `Infinity` на 35 бесконечно — синхронно,
  в единственном потоке процесса. Имя хоста попадает в этот код из ответа Search
  Console и из сохранённых записей аккаунтов, поэтому одно некорректное могло
  повесить сервер. Теперь метки отвергаются за пределами DNS-лимитов, каждое
  умножение и сложение проверяется, а код-поинт вне диапазона Unicode
  отклоняется.

## [0.6.7] — 2026-08-23

Все даты, которые приложение запрашивало у Search Console, были неверными —
причём тремя разными способами сразу. **После обновления цифры сдвинутся** —
до него они были неправильными.

### Исправлено
- **Даты считаются в часовом поясе Search Console.** Дневные строки размечены
  по `America/Los_Angeles`, а все окна строились из
  `toISOString().slice(0, 10)`, то есть по UTC. Примерно треть суток по
  европейскому времени приложение просило дату, которой у данных ещё нет, и
  молча получало меньше, чем думало.
- **Окно в N дней теперь содержит N дней.** `gscDateRange(days)` строил
  включительный диапазон от `now-days` до `now`, а это `days + 1` дат. Дашборд
  сравнивал 8 текущих дней с 7 предыдущими, поэтому каждая дельта «vs previous»
  была завышена примерно на седьмую часть при 7 днях и на ~3,6% при 28.
  (спасибо @klimenkoalex — [#3](https://github.com/izzipizzy/gsc-hub/pull/3))
- **Периоды заканчиваются последним завершённым днём.** Сегодняшний день ещё
  набирается, поэтому его включение сравнивало неполный день с полными: утром
  дельта уходила в сильный минус и выправлялась к вечеру — целиком как артефакт
  того, в какой час вы посмотрели.
- **Экспорт CSV использует то же окно, что и экран.** У него были свои функции
  для дат, поэтому один и тот же `days` давал разные цифры в интерфейсе и в
  файле.
- Арифметика дней больше не вычитает 86 400 000 миллисекунд — на переходе
  на летнее время в целевой зоне это давало сдвиг. Даты обрабатываются как
  строки `YYYY-MM-DD`, и тесты проходят одинаково под `TZ=UTC`,
  `Europe/Moscow` и `America/Los_Angeles`.
- Два окна в сравнении decay равны по длине и больше не делят общую дату,
  поэтому трафик одного дня не попадает в обе половины.

### Добавлено
- **Сегодняшний день — отдельная строка на дашборде**, подписанная датой по
  версии Search Console и помеченная как ещё набирающаяся. Без дельты — с
  неполным днём нечего честно сравнивать, — и с явным сообщением, если часть
  свойств прочитать не удалось, вместо подачи неполной суммы за полную.
  Загружается после отрисовки страницы, поскольку стоит по запросу на свойство.
- **Сравнение исчезает, когда сравнивать не с чем.** Search Console хранит около
  16 месяцев, поэтому за половиной этого срока предыдущий период попадает в
  пустоту и каждый сайт показывал уверенные −100%. Теперь дельты скрыты, а
  второй fan-out не выполняется — вдвое меньше запросов на длинных диапазонах.

## [0.6.6] — 2026-08-23

Исправления к v0.6.5 и ограниченный экспорт CSV.

**`EXPOSED_MODE=0` в v0.6.5 не работал.** В release notes было сказано, что он
возвращает однопользовательский режим в доверенной сети. На деле он глушил
только один из двух сигналов guard'а, поэтому инстанс, открытый по адресу из LAN
или по имени `.local`, всё равно отдавал 503 — ровно в том случае, ради которого
флаг и существует. Если вы его задали и всё равно получали 503 — вот почему.

### Исправлено
- `EXPOSED_MODE` теперь приоритетнее и настроенного origin, и хоста запроса, в
  обе стороны. Задать его — значит сделать утверждение о деплое, и когда
  учитывается половина, это хуже, чем если бы не учитывалось ничего.
- Нераспознанное значение `EXPOSED_MODE` — `treu`, `yes`, `2` — больше не
  проваливается в автоопределение. Опечатка в «этот инстанс выставлен наружу» не
  должна читаться как «решай сам», поэтому всё, что не является выключающим
  значением, означает exposed.
- IPv6-адреса loopback разбираются, а не сравниваются как строки. `new URL()`
  переписывает `::ffff:127.0.0.1` в `::ffff:7f00:1`, поэтому форма, которая
  реально приходит, считалась публичной — неожиданный 503 на честно локальном
  деплое.
- Бренд-термины длиной до трёх символов матчатся по границам слов, от четырёх —
  по-прежнему подстрокой. В v0.6.5 граница стояла на пяти, из-за чего
  четырёхбуквенный бренд переставал находиться в `brandlogin` и `mybrand`.

### Добавлено
- Экспорт CSV читает дальше 25 000 строк. Больше одного ответа Search Console не
  отдаёт, поэтому свойство покрупнее экспортировалось файлом, который просто
  обрывался — без ошибки, без предупреждения, без пометки внутри файла. Обход
  ограничен `GSC_EXPORT_MAX_ROWS` (по умолчанию 250 000), передаётся потоком и
  идёт со скоростью скачивания, а не копится в памяти, и прекращается при отмене
  загрузки. Если обход остановил именно лимит, последняя строка файла об этом
  сообщает.
  (спасибо @klimenkoalex — [#4](https://github.com/izzipizzy/gsc-hub/pull/4))
- `GSC_EXPORT_MAX_ROWS` и `GSC_EXPORT_PAGE_SIZE` — оба разбираются как
  положительные целые и зажимаются: размер страницы до 25 000 строк, которые
  помещаются в один ответ, потому что запрос большего молча пропускает всё, что
  за ним.

## [0.6.5] — 2026-08-23

Релиз про безопасность и исправление v0.6.3.

**v0.6.3 обещал больше, чем делал.** В нём было сказано, что приложение
перестаёт проваливаться в анонимного локального админа везде, кроме loopback. На
деле приватные диапазоны IP (`10.x`, `192.168.x`, `172.16–31.x`) и имена
`.local` считались локальными, поэтому инстанс в LAN, VPN или Docker-сети
по-прежнему отдавал полный админский доступ любому, кто до него дотянется. Если
вы разворачивали 0.6.3 или 0.6.4 не на `localhost` — этот релиз делает то, что
было заявлено в том.

### Ломающее
- Приложение, открытое по адресу из LAN или по имени `.local`, теперь отдаёт
  503, если логин не настроен, — тогда как 0.6.3 и 0.6.4 его обслуживали. Если
  эта сеть доверенная и нужен прежний однопользовательский режим, задайте
  `EXPOSED_MODE=0` явно. Если недоверенная — задайте `ADMIN_EMAIL` и
  `ADMIN_PASSWORD`.

### Безопасность
- Локальным считается только настоящий loopback: `localhost`, `*.localhost`,
  весь блок `127.0.0.0/8`, `::1` и IPv4-mapped loopback. «Не маршрутизируется из
  интернета» — не то же самое, что «доступно только этой машине»: сосед по
  Wi-Fi, VPN или Docker-сети прекрасно достаёт `192.168.1.20` и `gsc.local`.
- Незаданный origin считается exposed, а не loopback. Туннель публикует
  контейнер, не сообщая бэкенду нового URL, поэтому отсутствие `ORIGIN` ничего
  не говорит о том, кто может достучаться до приложения.
- Пустой `ORIGIN` больше не затеняет `AUTH_URL`. Compose подставляет незаданную
  переменную пустой строкой, поэтому `ORIGIN: ${ORIGIN}` без значения отбрасывал
  корректный `AUTH_URL` и загонял приложение в случай выше.
- Guard теперь считает exposed и запрос, пришедший на не-loopback хост.
  Настроенный origin не видит того, кто публикует приложение помимо него —
  туннель, лейбл OrbStack, бинд на `0.0.0.0`, — поэтому достаточно любого из
  двух сигналов. `EXPOSED_MODE=0` глушит оба.
- Проверка exposed требует именно админа, а не любого пользователя. `manager` —
  пользователь, но не имеет доступа к `/setup` и `/admin/users`, поэтому
  инстанс, где остался только он, работал без возможности им управлять.
- Проверка «первый ли это админ» перепроверяется внутри транзакции — две
  одновременные отправки setup больше не могут создать двух админов.
- Экспорт CSV нейтрализует ведущие `=`, `+`, `-` и `@` в текстовых полях, в том
  числе когда префикс спрятан за пробелом, табом или переводом каретки.
  Поисковые запросы попадают в файл как есть, а начать запрос с `=` может кто
  угодно. Числа не трогаются: клики, CTR и позиция без изменений.
- Смена пароля отзывает сессии этого пользователя. Сессии — случайные токены, не
  связанные с паролем, поэтому раньше все существующие оставались валидными
  оставшиеся 30 дней, включая того, ради кого пароль и меняли.

### Исправлено
- Троттлинг логина по адресу больше не использует лимит для аккаунта. За
  обратным прокси этот адрес — адрес прокси, поэтому пять неудачных попыток
  откуда угодно блокировали всех пользователей, включая владельца, на пятнадцать
  минут. Теперь у него свой, гораздо более мягкий лимит, а карта троттлера
  подметается, а не растёт всё время жизни процесса.

### Изменено
- `EXPOSED_MODE` объявлен в обоих compose-файлах, чтобы значение из окружения
  деплоя действительно доезжало до процесса.

## [0.6.4] — 2026-08-23

### Исправлено
- Бренд-термин по умолчанию берётся как registrable-метка, а не как
  предпоследняя. Для любого многосоставного публичного суффикса старое правило
  возвращало фрагмент самого суффикса — `co` для `example.co.uk`, `com` для
  `store.example.com.au`. Этот термин матчится как **подстрока** без учёта
  регистра, поэтому branded-разбивка не просто шумела, а инвертировалась:
  `discount code` и `cost of delivery` считались брендовыми, а `example login` —
  нет. Теперь метка выводится по Public Suffix List.
  (спасибо @klimenkoalex — [#5](https://github.com/izzipizzy/gsc-hub/pull/5))
- Учитываются приватные суффиксы: `user.github.io` даёт `user`, а не `github`;
  `name.blogspot.com` даёт `name`, а не `blogspot`.
- IP-хост возвращается целиком, а не проваливается в старое правило, которое
  выдавало октет — термин `168` матчит огромное количество запросов.

Пер-сайтовые переопределения в `site_branded_keywords` не затронуты и
по-прежнему приоритетнее умолчания. На сайтах с сохранённым переопределением
ничего не меняется.

Известное ограничение, заведено как [#8](https://github.com/izzipizzy/gsc-hub/issues/8):
разбивка всё ещё матчит термины подстрокой, поэтому короткое **ручное**
переопределение (`go`, `it`, `ai`) даёт те же ложные срабатывания, которые этот
релиз убирает из умолчаний.

## [0.6.3] — 2026-08-23

Релиз про безопасность. **Обновитесь, если приложение доступно не только по
loopback.** Два послабления, задуманные для однопользовательской установки на
localhost, могли отдать постороннему полный админский доступ ко всем
подключённым аккаунтам Search Console, если приложение было видно из интернета.

### Безопасность
- Инстанс на публичном origin больше не проваливается в анонимного локального
  админа. `decideRoute` пропускал **любой** запрос как админский, если логин был
  выключен — режим для loopback-установки, но проверки, что запрос пришёл с
  loopback, не было. Деплой, потерявший `ADMIN_EMAIL`/`ADMIN_PASSWORD` или
  поднявшийся на пустом volume, отдавал открытую панель. Теперь он не отдаёт
  ничего (503), пока логин не настроен.
- Setup-визард больше не доступен анонимно на публичном origin. `/setup`
  намеренно открыт, пока setup не завершён, — а на публичном хосте это значило,
  что инстанс забирает первый зашедший. При деплое наружу задавайте
  `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `ADMIN_EMAIL` и `ADMIN_PASSWORD`
  через переменные окружения.
- Отклонённая форма setup больше не оставляет приложение настроенным. Google-ключи
  писались до валидации пароля админа, а `isSetupComplete()` смотрит только на
  эти ключи — поэтому неудачная отправка переводила приложение из состояния
  «всё редиректит на /setup» в «настроено, логина нет, всё открыто». Теперь до
  принятия всех полей не пишется ничего, а записи идут одной транзакцией.
  (спасибо @klimenkoalex — [#2](https://github.com/izzipizzy/gsc-hub/pull/2))
- Exposed-режим всегда включает логин. `LOGIN_ENABLED` выставлялся только при
  создании первого админа, поэтому повторная отправка завершала setup с
  выключенным логином.
- Перенастройка завершённого setup теперь требует админа, а не принимает
  анонимный POST на `/setup`.
- Троттлинг логина больше не обходится пробелом. Поиск пользователя обрезает
  пробелы и приводит к нижнему регистру, а ключ троттлера — только регистр, так
  что `" admin@example.com"` был новой корзиной на пять попыток против того же
  хеша пароля. Рядом добавлена корзина по адресу — один клиент не может
  израсходовать полную квоту попыток на каждый из многих аккаунтов подряд.

### Добавлено
- `EXPOSED_MODE` принудительно задаёт режим exposed/loopback в обе стороны. По
  умолчанию он выводится из `ORIGIN` (с откатом на `AUTH_URL`): loopback-адреса,
  mDNS-имена `.local` и приватные диапазоны IP считаются не выставленными наружу.
- Ссылка на свойство в интерфейсе Search Console, открывающаяся под владеющим
  аккаунтом сразу на Performance → Search results.

## [0.6.2] — 2026-08-04

Релиз про надёжность на больших портфелях: пер-сайтовый fan-out больше не
плавит пул сокетов, а истёкший токен обновляется один раз, а не на каждый сайт.

### Исправлено
- Пер-сайтовые fan-out'ы ограничены 8 одновременными вызовами Search Console
  вместо одного соединения на каждое свойство. На аккаунте с ~200 сайтами
  неограниченный fan-out забивал пул сокетов, вся пачка падала с
  `UND_ERR_CONNECT_TIMEOUT`, и таблица сайтов рисовала прочерки. (спасибо @KuznetsovRA — [#1](https://github.com/izzipizzy/gsc-hub/pull/1))
- Истёкший access-токен обновляется один раз на аккаунт за fan-out. Общая
  запись аккаунта обновляется на месте, параллельные refresh'ы дедуплицируются —
  загрузка страницы с 200 сайтами больше не шлёт 200 запросов на token-endpoint.
  Такой всплеск Google мог отбить 400-ми, а те трактовались как `invalid_grant`
  и помечали аккаунт revoked.

### Изменено
- Параллелизм fan-out'а настраивается через `GSC_CONCURRENCY` (по умолчанию 8).
  URL Inspection работает у́же — `GSC_INSPECT_CONCURRENCY` (по умолчанию 4), потому
  что там ограничение по квоте (2000/день, 600/мин на сайт), а не по сокетам.

## [0.6.0] — 2026-07-18

Крупный релиз: полноценный пакет SEO-аналитики поверх Search Console — детальные
разборы по каждому сайту и сводный вид по всему портфелю, — плюс Bing/IndexNow,
проверки здоровья сайта и опциональный многопользовательский вход. Вся аналитика

### Добавлено

**Аналитика по сайту** — новая детальная страница `/properties/[site]` с табами:
- **Striking Distance** — запросы на позициях 4–20 с реальными показами (быстрые

- **Keyword Cannibalization** — запросы, где несколько своих URL конкурируют между
  собой, с явной разбивкой winner/loser.
- **CTR Benchmark** — фактический CTR по позициям против эталонной кривой + список
  «недобирающих» страниц.
- **Content Decay** — страницы, теряющие клики **или показы** относительно

- **Branded vs non-branded** — разбивка трафика по брендовым словам (редактируются
  per-site).
- **Site Health** — SSL (срок/издатель/грейд), Google Safe Browsing и Core Web

**Сводная аналитика по портфелю** — новый вид `/properties/portfolio` по всем
не-скрытым сайтам:
- Табы Striking / Cannibalization / CTR / Branded / Decay, **адресуемые через URL**

**Прочее**
- **Спарклайны** дневных кликов на карточках сайтов.

  `ADMIN_EMAIL`/`ADMIN_PASSWORD`.
- Улучшения `/properties`: фильтры мусорных запросов, произвольный диапазон дней,

### Изменено

  OAuth-токены плюс мелкий per-site конфиг (бренд-слова) и кэш внешних
