# Проверка страниц в Google

Экран **Проверка индексации** (`/index-check`) получает URL выбранного сайта из sitemap
и ищет точное совпадение адреса через XML River или DataForSEO. Открыть его можно
из навигации, настроек «Индексаторы» или кнопкой «Проверить в Google» на странице сайта.

Это проверка видимости URL через поисковую выдачу, а не Google URL Inspection.
«Найден в Google» означает точное совпадение в органических результатах.
«Не найден по запросу» не доказывает отсутствие страницы в индексе. Ошибка API,
незавершённая или пропущенная проверка не считаются отрицательным результатом.
Количество URL — размер полученного списка sitemap, а не размер индекса сайта.

## Настройки

В **Индексаторы → Проверка страниц в Google** заполните настройки нужного сервиса.
Настройки общие для всех сайтов; провайдеры сохраняются независимо.

| Сервис | Поля в интерфейсе | Переменные окружения |
|---|---|---|
| XML River | User ID, API-ключ из настроек сбора Google | `XMLRIVER_USER`, `XMLRIVER_KEY` |
| DataForSEO | API Login, API Password из API Access | `DATAFORSEO_LOGIN`, `DATAFORSEO_PASSWORD` |

У DataForSEO нужен именно API Password, а не пароль входа в кабинет.
Значения окружения имеют приоритет и недоступны для изменения через интерфейс.
Без окружения значения хранятся в существующем `app_config` локальной SQLite,
так же, как остальные ключи интеграций. Пустое поле при редактировании сохраняет
предыдущее значение. Кнопка удаления убирает значения из БД, но не из окружения.
Сохранённые секреты не выдаются в HTML, page data или ответы настроек.

Кнопка перехода к DataForSEO использует предоставленную владельцем проекта
реферальную ссылку. У XML River стоит обычная ссылка на сайт. API-документация
обоих сервисов открывается по прямым ссылкам. Адреса кнопок определены в
`src/lib/utils/index-check.ts`.

## Сценарий

1. Найдите сайты по адресу и выберите один или несколько (до 20). Поиск не учитывает регистр; очистка возвращает полный список. Аккаунт показан под адресом и не участвует в поиске. Стрелки перемещают активный вариант, Enter переключает выбор, Escape закрывает список.
2. При необходимости укажите конкретный sitemap URL. Если поле пустое, сначала
   объединяются зарегистрированные адреса из GSC и декларации `Sitemap:` из
   `robots.txt`; отсутствие адресов или недоступность обоих источников дают явную ошибку.
3. Нажмите **Получить URL из sitemap**. Получение списка не вызывает платные API.
   Перед запуском доступны число уникальных URL, сами адреса и исходные карты.
4. Выберите настроенного провайдера и нажмите кнопку проверки с числом URL и
   именем сервиса. Это явный запуск оплачиваемых запросов по тарифу провайдера.
5. Следите за прогрессом, статусами, временем проверки и ошибками по страницам.
   Фильтр статуса и постраничный вывод позволяют просмотреть весь список.
6. **Скопировать ненайденные URL сайта** копирует все адреса с результатом
   `not_found` из открытой проверки, независимо от фильтра и страницы таблицы.
   В очереди доступна отдельная кнопка для всех сайтов; повторяющиеся адреса удаляются.
   В буфере — по одному URL на строку, без ошибок и непроверенных страниц.
   Если браузер запрещает доступ к буферу, список можно выделить и скопировать вручную.
   Кнопки работают и с сохранённой историей, без повторных платных запросов.

Вложенные sitemap index, повторяющиеся карты и URL, XML namespaces и gzip
обрабатываются. Допустимы только публичные HTTP(S)-адреса того же домена
(`www` и без `www` считаются одним доменом). Чужие домены не пропускаются молча:
загрузка списка завершается ошибкой. Ограничения: 200 карт, 5000 уникальных URL,
документ до 4 МБ, суммарное время обхода до двух минут. Для больших сайтов
выберите отдельный дочерний sitemap. HTTP-редиректы и DNS-адреса проверяются
существующим загрузчиком `readPublicDocument`: внутренние, loopback и служебные
адреса блокируются, проверенный IP закрепляется на время соединения.

## Контракты провайдеров

Параметры проверены по официальной документации 2026-11-12. Запросы идут только
в Google; корневой XML-тег `yandexsearch` у XML River — формат ответа, а не выбор Яндекса.

### XML River

- `GET https://xmlriver.com/search/xml`, `user`, `key`, `query=<URL>`,
  `inindex=1`, `strict=1`, `page=1`, `groupby=10`.
- География и прочие параметры Google наследуются из настроек кабинета провайдера.
- В режиме `inindex` URL ограничен 1400 символами. HTTP-клиент ожидает до 65 секунд:
  документация требует не обрывать синхронный запрос раньше одной минуты.
- Сопоставляются только URL документов из `response/results/grouping/group/doc`.
  Посторонние блоки, реклама, sitelinks и поле `found` не являются доказательством.
  `found` без платной опции вообще может содержать значение по умолчанию 100.
- Код `15` — нет результатов; `31/42/45` — авторизация/доступ;
  `200` — баланс; `110/111/115` — лимит каналов. Неизвестный XML или другой код — ошибка.

Официальные источники: [подключение](https://xmlriver.com/api/api-connect/),
[параметры Google](https://xmlriver.com/apidoc/api-about/),
[формат ответа](https://xmlriver.com/api/api-answer/),
[коды ошибок](https://xmlriver.com/api/api-errors/),
[синхронный режим](https://xmlriver.com/api/api-alt/).

### DataForSEO

- `POST https://api.dataforseo.com/v3/serp/google/organic/live/advanced`,
  HTTP Basic из API Login/API Password. Один task на запрос.
- `keyword=site:<URL>`, `location_code=2840` (США), `language_code=en`,
  `device=desktop`, `depth=10`. Проценты и плюсы экранируются с учётом декодирования API.
  Максимум keyword — 700 символов; слишком длинный URL получает ошибку без отправки.
- `site:` имеет повышенный тариф: документация указывает множитель 5.
  Точную стоимость и лимиты расходов нужно проверить в кабинете перед запуском.
- Сравниваются только `items` типа `organic`. Верхний и task-level `status_code`
  проверяются независимо. `40102` — нет результатов; `40106` — частичная выдача:
  точное совпадение можно показать, его отсутствие считается неизвестным результатом.
- Ошибки доступа (`40100` и др.), баланса/лимита расходов (`40200/40203/40210`),
  rate limit (`40202/40205/40206/40209`) и неизвестные ошибки различаются.

Официальные источники: [Live Advanced](https://docs.dataforseo.com/v3/serp/google/organic/live/advanced/),
[аутентификация](https://docs.dataforseo.com/v3/auth/),
[коды ошибок](https://docs.dataforseo.com/v3/appendix/errors/).

## Выполнение и срок жизни результатов

Для каждого провайдера допускается один активный запуск на процесс сервера.
XML River выполняет до 10 одновременных запросов: в **Индексаторы** можно сохранить
целое число потоков от 1 до 10, по умолчанию 10. DataForSEO обрабатывается
последовательно с паузой не меньше секунды. Настройки фиксируются в запуске;
их изменение применяется к следующим проверкам.

Для обоих сервисов настраиваются **повторы после ошибки** (0–10, по умолчанию 3)
и **пауза между повторами** (1–60 минут, по умолчанию 3). Это дополнительные попытки:
при трёх повторах один URL может отправиться до четырёх раз. Перед запуском
интерфейс показывает верхнюю границу платных запросов с учётом повторов. После
тайм-аута результат и списание неизвестны, поэтому повтор может оплачиваться снова.
Повтор HTTP-запроса запуска для той же пары список/провайдер по-прежнему возвращает
тот же run ID, не создавая второй запуск.

Повторяются временные сетевые ошибки, тайм-ауты, ошибки сервиса 5xx и занятые
каналы XML River (110/111/115). При лимите каналов приостанавливаются все новые
обращения этого запуска. Пауза может быть больше выбранной: учитываются
`Retry-After` и десятиминутная блокировка XML River с кодом 115. Авторизация,
недостаток средств и некорректный URL не повторяются. Если лимит каналов не снят
после всех попыток или три запроса подряд исчерпали попытки с ошибками, оставшаяся
очередь останавливается с объяснением. Уже отправленные обращения ограничены
тайм-аутом и сохраняют полученные ответы.

Каждая попытка ожидает ответ до 65 секунд; дополнительное ограничение исполнителя
70 секунд завершает даже зависший транспорт. Отмена работает во время запроса
и паузы. Видны обработанные URL, активные запросы, очередь, ожидание повтора,
отсчёт до следующей попытки и номер попытки по каждой странице. Ошибки и пропуски
не превращаются в отрицательные ответы Google.

### Баланс в настройках

Баланс загружается отдельно от страницы и обновляется кнопкой:
- XML River: `GET /api/get_balance/`, сумма основного и бонусного счетов в рублях.
- DataForSEO: `GET /v3/appendix/user_data`, `tasks[0].result[0].money.balance` в USD.

Это методы данных аккаунта, они не отправляют запросы в поисковик. Ожидание
ограничено 15 секундами. Ошибка показывается как недоступность, а не как нулевой
баланс; ключи и посторонние данные аккаунта не возвращаются в браузер.
Официальные контракты: [XML River](https://xmlriver.com/api/api-methods/),
[DataForSEO](https://docs.dataforseo.com/v3/appendix/user_data/).

## Постоянная история

Каждый запуск сохраняется в SQLite отдельно: сайт и аккаунт, сервис, Google,
время начала и завершения, общее число URL, число проверенных страниц и найденных
точных совпадений, состояние запуска, настройки потоков/повторов и все результаты по URL с номерами попыток. История доступна
на `/index-check`, фильтруется по выбранному сайту и показывает по 50 запусков.
Кнопка «Результаты» открывает сохранённый снимок; ссылка `?run=<id>` продолжает
работать после перезагрузки браузера и перезапуска приложения. Новые проверки
не заменяют старые.

«Проверено» в истории включает только `found` и `not_found`; ошибки и пропуски
не считаются отрицательными ответами. Если ни одного достоверного ответа нет,
количество найденных хранится как `NULL` и показывается прочерком. Ноль означает,
что есть проверенные страницы, но точных совпадений среди них не найдено.
При частичной проверке это число относится только к проверенным страницам.

Запись создаётся до первого платного запроса, прогресс фиксируется до и после
каждого обращения. Если запись в БД недоступна до запуска, запросы не отправляются;
ошибка записи во время проверки останавливает дальнейшие обращения. Если итог
сохранить не удалось, интерфейс предупреждает об этом.

После перезапуска незавершённый запуск получает состояние «Прервана сервером».
Полученные ответы сохраняются; текущий запрос отмечается как неизвестный результат
с возможным списанием, ещё не отправленные страницы — как пропущенные.
После перезапуска автоматического продолжения, в том числе ожидавших повторов, нет. Для новой проверки нужно
заново получить список и явно запустить сервис.

Черновики sitemap и рабочий кеш по-прежнему ограничены 20 списками/запусками
и 30 минутами; это не ограничивает постоянную историю. Данные находятся в
`index_check_runs` и `index_check_results` основной SQLite БД. Добавление таблиц
не меняет существующие настройки и данные. Резервная копия БД включает историю;
удаление БД удаляет её вместе с остальными данными приложения.

## Локальная проверка

`pnpm check`, `pnpm test`, `pnpm build`. Тесты провайдеров, sitemap, очереди и истории
используют подменённые ответы и не отправляют платных запросов. Проверки истории
охватывают повторные запуски, перезапуск, прерывание и ошибки записи в SQLite.

### Определение sitemap

При автоматическом выборе объединяются все зарегистрированные адреса выбранного
сайта/аккаунта из GSC Sitemaps API и все директивы Sitemap из robots.txt. Дубликаты
удаляются, вложенные карты обходятся полностью в существующих пределах. Адрес
`/sitemap.xml` не угадывается. Если один источник недоступен, используются объявления
другого с предупреждением; если адресов нет — показана ошибка и предложен ручной URL.
Ручной ввод использует только указанный адрес. Запрос списка GSC ограничен 10 секундами;
он не отправляет sitemap в Google и не запускает платную проверку.

### Несколько сайтов

После выбора нескольких сайтов кнопка получения URL готовит отдельный список для
каждого (не больше двух параллельных загрузок). Ручной Sitemap URL доступен при
одном выбранном сайте. Если подготовка какого-либо сайта не удалась, платный запуск
блокируется: исправьте адрес или уберите сайт и получите URL заново. Предпросмотр
показывает общее число сайтов, URL и максимум запросов с повторами; в списках отображаются
первые 100 URL каждого сайта, в проверку попадают все подготовленные страницы.

Одна кнопка запуска создаёт очередь: сайты выполняются последовательно, внутри
каждого действует общий лимит потоков провайдера. Каждый сайт сразу получает
собственную запись истории, связанную с очередью. Видны состояния сайтов и общий
прогресс; можно открыть детали любого сайта и остановить всю очередь. Ошибки
авторизации, баланса, исчерпание каналов или аварийная остановка провайдера не
запускают последующие сайты вслепую. Завершённые результаты сохраняются.

Ссылка `?batch=<id>` восстанавливает очередь и её результаты после перезагрузки
браузера. После перезапуска сервера активные и ожидающие сайты помечаются прерванными,
без автоматического продолжения платных проверок. Повтор запроса запуска той же
группы списков возвращает существующую очередь.
