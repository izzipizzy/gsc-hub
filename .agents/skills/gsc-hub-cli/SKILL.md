# gsc-hub из терминала

CLI обращается к машинному API существующего хаба. Ключ ограничивает доступ
к сайтам; CLI не обходит эту область и не обращается к локальной SQLite.

## Подключение

Требуется Node 22.18+. Из checkout проекта установи `node cli/install.mjs --cli`;
без установки доступна команда `node cli/bin/gsc-hub.mjs`.
CLI и скиллы можно ставить независимо из минимального checkout каталогов
`cli` и `.agents/skills`. `node cli/install.mjs --check` проверяет Node/npm,
`--skills --agent codex` ставит скиллы для Codex, `--agent claude` — для Claude
Code. Существующие скиллы заменяются только с `--force`. Подготовка macOS и
Windows описана в `docs/CLIENT-INSTALL.md` репозитория. Не устанавливай серверные
модули для клиента: внешних runtime npm-зависимостей у него нет.
Адрес задаётся через `GSC_HUB_URL` или `--url`, ключ — только через
`GSC_HUB_KEY` в окружении. Ключ создаётся на `/api` нужного хаба.
Не проси присылать ключ в чат и не помещай его в аргументы, отчёты или Git.
Для удалённого хаба используй HTTPS. По умолчанию адрес — `http://localhost:5173`.

Начни с `gsc-hub --help`, затем `gsc-hub sites --days 28 --json`.
Бери точное значение `site` из ответа (например, `sc-domain:example.com`),
не угадывай property. Отсутствующий сайт может быть скрыт областью ключа.
Для обработки результатов предпочитай `--json`: stdout содержит результат,
stderr — JSON ошибки, код выхода ненулевой при сбое. Не интерпретируй ошибку
или `partial` как нулевой трафик. `--timeout 120000` увеличивает бюджет
долгого запроса; период `--days` допускает 1..480 дней.

## Команды и сценарии

| Задача | Команда |
|---|---|
| Запросы сайта | `gsc-hub queries --site SITE --days 28 --limit 100 --json` |
| Страницы по точному запросу | `gsc-hub query-pages --site SITE --query "запрос" --days 28 --json` |
| Позиции 4–20 | `gsc-hub striking --site SITE --days 28 --limit 100 --json` |
| Конкуренция своих страниц | `gsc-hub cannibalization --site SITE --days 28 --json` |
| Недобор CTR | `gsc-hub ctr --site SITE --days 28 --json` |
| Просадка страниц | `gsc-hub decay --site SITE --days 28 --json` |
| Страны | `gsc-hub countries --site SITE --days 28 --json` |
| История действий | `gsc-hub events --site SITE --json` |

`SITE` — подставляемое значение, не буквальное имя сайта.
`striking` и `events` без `--site` работают по всем доступным сайтам.

Для плана роста сопоставь striking, query-pages и ctr; сначала отдели
каннибализацию и плохой сниппет от кандидатов на ссылки.
Для просадки сопоставь decay и events: после склейки сравнивать только
один домен недостаточно. Для обзора портфеля начни с sites и striking без
`--site`, затем разбирай значимые сайты отдельно. Не суммируй CTR и позиции;
указывай период и частичные ошибки, отделяй факты от гипотез.

Это терминальные аналоги инструментов `list_sites`, `site_queries`,
`query_pages`, `striking_keywords`, `cannibalization`, `ctr_benchmark`,
`decay`, `site_countries`, `site_events` из существующих SEO-скиллов хаба.
Детали API доступны через `gsc-hub doc`, список скиллов — `gsc-hub skills`.
`gsc-hub skills --name gsc-hub-cli` печатает этот SKILL.md.

## Запись склейки

`merge` записывает событие о **фактически выполненной** склейке, а не
настраивает редирект и не меняет сайт. Выполняй только когда пользователь
поручил записать конкретные сайт, донор и дату. Уже данное поручение не
требует повторного подтверждения. Дата — реальный день склейки; без
`--date` сервер использует сегодняшний день UTC.

```bash
gsc-hub merge --site sc-domain:example.com --donor donor.example \
  --date 2026-11-07 --yes --json
```

CLI требует `--yes` и не отправляет запрос без него. Одинаковые сайт,
донор и дата идемпотентны; после сетевого сбоя сначала проверь `events`.
Других записывающих команд, покупок и платных отправок в CLI нет.

Коды выхода: 2 — аргументы/настройка; 3 — авторизация; 4 — HTTP/сеть;
5 — ошибка инструмента или протокола. При 401/403 проверь конфигурацию
ключа, при 404 — видимость ресурса и версию сервера, не подбирай чужие сайты.
